# CampusConnect 프론트엔드 통합본 안내

## 이번 통합 범위

- 로그인 / 회원가입: Spring Boot 인증 API, 이메일 코드 발송·검증, 닉네임 중복 확인, JWT 저장 및 `/users/me` 복원
- 중고책: 목록·검색·상세·등록·수정·삭제·판매 상태 변경·찜·구매자 후보 조회
- 프로젝트: 목록·상세·등록·수정·삭제·마감·지원·지원자 조회·승인/거절·지원 취소
- 채팅: REST 채팅방 생성/조회, 메시지 전송, 읽음 처리, 2.5초 간격 신규 메시지 조회
- 마이페이지: 내 도서·프로젝트·찜·지원 내역·받은 후기
- 거래 후기: 판매 완료된 책의 구매자에게 별점 및 후기 등록

## 백엔드 원본 보호

이 ZIP에는 프론트엔드 파일만 포함됩니다. `backend/` 폴더는 없으며, GitHub `develop` 백엔드 코드는 API 계약 확인 목적으로만 읽었습니다. 백엔드 파일을 수정하거나 커밋하지 않았습니다.

## 실행 방법 (Windows PowerShell)

1. Spring Boot 백엔드를 기존 방식으로 실행하고 MySQL 연결을 확인합니다. 기본 주소는 `http://localhost:8080`입니다.
2. 이 압축을 새 폴더에 풉니다.
3. Node.js는 `react-router@8.5.1`의 엔진 조건에 맞춰 `22.22.0` 이상을 사용합니다.
4. `frontend` 폴더에서 아래 명령을 실행합니다.

```powershell
npm ci
npm.cmd run dev
```

5. 브라우저에서 `http://localhost:5173`에 접속합니다.

Vite 설정의 `/api` 프록시가 요청을 `http://localhost:8080`으로 전달합니다. 따라서 개발 환경에서는 별도 CORS 우회 설정이 필요하지 않습니다.

## 반드시 확인할 백엔드 제약

1. **프로젝트 생성 응답**: 현재 `POST /api/v1/projects`는 생성된 게시글 ID가 아니라 성공 문자열을 돌려줍니다. 프론트는 등록 후 목록으로 이동합니다.
2. **프로젝트 생성 필드**: 현재 Controller가 받는 `ProjectPostDto`에는 `title`, `content`, `capacity`, `category`, `location`만 있습니다. 시작일·종료일·자격요건·태그 등은 현재 생성 서비스에서 저장되지 않아 입력 화면에서 제외했습니다.
3. **프로젝트 수정 필드**: 수정 요청 DTO에는 추가 필드가 있지만 서비스의 실제 저장 메서드는 제목·내용·모집 인원·분야·장소만 반영합니다. 이 범위만 수정 화면에 노출했습니다.
4. **채팅 실시간성**: 메시지 전송과 읽음 처리는 토큰 인증 REST API를 이용합니다. 새 메시지는 2.5초 주기로 조회합니다. WebSocket/STOMP 푸시 연결은 이번 ZIP에 포함하지 않았습니다.
5. **후기**: 백엔드는 별점과 댓글만 저장합니다. 기존 프론트의 후기 태그는 실제 DTO에 없으므로 제거했습니다.
6. **프로젝트 삭제**: 지원 내역이 존재하는 프로젝트는 `project_application.project_post_id` 외래 키 제약 때문에 현재 백엔드 삭제 로직에서 삭제가 실패할 수 있습니다. 지원 내역 처리 또는 삭제 정책 보완이 필요한 백엔드 수정사항입니다. 이번 프론트엔드 수정에서는 백엔드 원본을 변경하지 않았습니다.
7. **미지원 데이터**: 알림 API, 거래 내역 별도 엔티티, 매너 온도, 책 사진·상태 등 현재 API에 없는 데이터는 실제 서버 기능처럼 표시하지 않습니다. 서버 연동 알림 기능은 구현 범위에서 제외했습니다.

## 테스트 순서

- [ ] 회원가입: `@syu.ac.kr` 이메일로 코드 발송 → 코드 확인 → 닉네임 중복 확인 → 회원가입
- [ ] 로그인 / 새로고침 후 로그인 상태 유지 / 로그아웃
- [ ] 도서 등록 → 목록 검색 → 상세 → 수정 → 찜 → 찜 목록 확인
- [ ] 다른 계정으로 도서에 채팅 → 판매자 계정에서 채팅 상대 확인 → 판매 완료 및 구매자 지정
- [ ] 구매자 계정에서 거래 후기 작성 → 판매자 마이페이지에서 받은 후기 확인
- [ ] 프로젝트 등록 → 목록·상세 → 다른 계정으로 지원 → 작성자 승인/거절
- [ ] 지원자가 마이페이지에서 대기 중 지원 취소
- [ ] 두 계정으로 메시지 전송 및 읽음 처리 확인
